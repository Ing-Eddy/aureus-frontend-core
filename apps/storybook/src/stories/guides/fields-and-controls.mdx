# Fields & controls

Every kind of input in `@aureus-core/ui` comes as a pair:

- a **field** (`TextField`) is a general-purpose input. Use it anywhere, controlled or uncontrolled.
- a **control** (`TextControl`) is the same input bound to a react-hook-form form.

With the same props, a field and its control render **the same markup**, so a form looks the same whichever you use. A control renders its field internally.

Available families:

| Family   | Field           | Control           | Button inside the input                     |
| -------- | --------------- | ----------------- | ------------------------------------------- |
| Text     | `TextField`     | `TextControl`     | Optional and configurable (`action`)        |
| Password | `PasswordField` | `PasswordControl` | Always the show/hide toggle (no `action`)   |
| Text area | `TextAreaField` | `TextAreaControl` | Optional (`action`), in a footer bar below the text |
| Number   | `NumberField`   | `NumberControl`   | Step buttons (stacked or split) plus an optional `action` |
| Select   | `SelectField`   | `SelectControl`   | Chevron, optional clear (✕) and an optional `action` |
| Checkbox | `CheckboxField` | `CheckboxControl` | No frame: an optional `action` at the end of the row |
| Checkbox group | `CheckboxGroupField` | `CheckboxGroupControl` | No frame: one box per option |
| Radio group | `RadioGroupField` | `RadioGroupControl` | No frame: one radio per option, or segments |
| Switch | `SwitchField` | `SwitchControl` | No frame: an optional `action` at the end of the row |
| OTP | `OtpField` | `OtpControl` | Boxes over one input; optional show/hide toggle and `action` |
| File | `FileField` | `FileControl` | The choose button (the native file input); optional dropzone and `action` |
| Avatar | `AvatarField` | `AvatarControl` | A circular camera button on the avatar; the avatar opens a dialog (change, edit, remove, open); optional `action` |
| Slider | `SliderField` | `SliderControl` | No frame: a track with one or two thumbs; optional number inputs and `action` |

Every family shares the same view, so all fields look alike.

## Using a field

```tsx
import { TextField } from "@aureus-core/ui/components/text-field";
import { SearchIcon } from "lucide-react";

<TextField
  label="Search"
  helperText="At least 3 characters"
  loading={isSearching}
  loadingLabel="Searching"
  action={{ children: <SearchIcon />, "aria-label": "Search", tooltip: "Run search", onClick: search }}
/>;
```

## Using a control

Controls are always rendered inside a react-hook-form `FormProvider`. The form owns values, default values and validation (usually a schema passed through a resolver); a control only takes the field `name` and visual props. There is no `control` or `rules` prop, and no type parameter to write.

```tsx
import { TextControl } from "@aureus-core/ui/components/text-control";
import { zodResolver } from "@hookform/resolvers/zod";
import { FormProvider, useForm } from "react-hook-form";
import { z } from "zod";

const schema = z.object({ username: z.string().min(3, "Use at least 3 characters.") });

function ProfileForm() {
  const form = useForm({ resolver: zodResolver(schema), defaultValues: { username: "" } });

  return (
    <FormProvider {...form}>
      <form noValidate onSubmit={form.handleSubmit(save)}>
        <TextControl name="username" label="Username" required helperText="Visible to others" />
      </form>
    </FormProvider>
  );
}
```

- **Validation messages appear in the helper slot.** While the field has an error in the form state, its message replaces `helperText`, the input gets `aria-invalid`, and the message is announced. Once the value is fixed, `helperText` comes back.
- **Always pass `defaultValues`.** `name` is a plain string, so a typo cannot be caught by TypeScript. In development, a control warns when its `name` is not among the form's default values.
- **Outside a `FormProvider`, a control throws** an error that says so.

## `disabled` vs `loading`

Both make the input unavailable, but they mean different things to the form:

| Prop       | Input    | Spinner | Value submitted |
| ---------- | -------- | ------- | --------------- |
| `disabled` | disabled | no      | **no**          |
| `loading`  | disabled | yes     | **yes**         |

Use `loading` while you are checking or fetching something for a field whose value must still be sent.

## Shared props

Every field and control accepts these props:

| Prop                          | What it does                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------------------------- |
| `label`                       | Text above the input, and its accessible name.                                                     |
| `required`                    | Red asterisk and `aria-required`. It adds no validation rule.                                      |
| `info` / `infoLabel`          | Info button at the far end of the label row, with a tooltip that also opens on tap. `infoLabel` names the button and is required with `info`. |
| `helperText`                  | Text below the input, part of its accessible description.                                          |
| `loading` / `disabled`        | See above.                                                                                         |
| `action`                      | One button inside the input frame: text or icon, `tooltip`, and any button prop.                   |
| `className` / `classNames`    | Extra classes for the root, or per part: `root`, `header`, `label`, `requiredMark`, `info`, `control`, `input`, `helper`, `action`. |
| `loadingLabel`                | Accessible name of the spinner, required with `loading`. There is no default text.                 |

A field also takes `error` and `errorMessage`; a control gets both from the form.

## Password

```tsx
import { PasswordControl } from "@aureus-core/ui/components/password-control";

const toggle = { showPasswordLabel: "Show password", hidePasswordLabel: "Hide password" };

<PasswordControl {...toggle} name="password" label="Password" required />
<PasswordControl {...toggle} name="confirm" label="Repeat password" autoComplete="new-password" />
```

- **The toggle's names are yours.** `showPasswordLabel` and `hidePasswordLabel` are always required, because the toggle is always shown.
- **The toggle is built in.** It shows or hides the password, has `aria-pressed` and keeps focus and the caret in the input when clicked. Submitting the form hides the password again. There is no `action` prop.
- **Controlled visibility.** Pass `visible` and `onVisibleChange` to drive several fields at once, for example from a "Show passwords" checkbox. `defaultVisible` sets the initial state when uncontrolled.
- **Autocomplete.** The default is `current-password` (sign-in). Use `new-password` on sign-up and change-password forms, so password managers offer to generate one.
- **Confirmation.** Put the match rule in the schema, on the confirmation path (with zod, a `refine` with `path: ["confirm"]`); its message appears on that control.

## Text area

```tsx
import { TextAreaField } from "@aureus-core/ui/components/text-area-field";

<TextAreaField
  label="Comment"
  minRows={3}
  maxRows={8}
  maxLength={280}
  showCount
  countLabel={(count, max) => `${(max ?? 0) - count} characters remaining`}
  actionShortcut
  action={{ children: "Post", variant: "default", onClick: post }}
/>;
```

- **Live height.** The field grows with its content from `minRows` to `maxRows` lines, then scrolls. Users can also drag it taller or shorter; the height they choose becomes the new minimum. `resize={false}` removes the handle.
- **Footer bar.** The spinner, the counter and the `action` live in a bar along the bottom edge of the frame, so the button follows any height change and never covers the text. The bar only appears when it has something to show.
- **Counter.** `showCount` shows "count/maxLength" (or the count alone) and turns red at the limit. It requires `countLabel(count, maxLength?)`, the text screen readers get in the field's description, announced once the user pauses typing. You decide whether it says what remains or what was typed.
- **Shortcut.** `actionShortcut` lets Ctrl+Enter (Cmd+Enter on macOS) press the action; Enter alone still adds a new line.

## Number

```tsx
import { NumberControl } from "@aureus-core/ui/components/number-control";
import { NumberField } from "@aureus-core/ui/components/number-field";

const steps = { incrementLabel: "Increase", decrementLabel: "Decrease" };

<NumberField {...steps} label="Quantity" min={0} />                          // 122345
<NumberField {...steps} label="Units" grouping />                            // 123,345
<NumberField {...steps} label="Budget" currency="USD" decimals={0} grouping /> // $ 12,000
<NumberField label="Rate" suffix="%" decimals={3} stepper={false} />         // 4.125 %
<NumberControl {...steps} name="amount" label="Amount" currency="USD" decimals={2} padDecimals grouping />
```

- **Every prop is independent and opt-in.** Without props the field shows digits as typed. `grouping`, `decimals`, `padDecimals`, `currency`, `prefix`, `suffix`, `align` and the negative format never change each other's defaults: `currency` only adds a symbol. The implementation decides which combination is right.
- **The value is `number | null`.** The control stores a number in the form, so schemas such as `z.number()` work directly.
- **Step buttons.** `stepperLayout="stacked"` (▲▼ at the end) or `"split"` (− and + on each side); on touch screens stacked becomes split automatically. `stepper={false}` hides them. While they are shown, `incrementLabel` and `decrementLabel` are required. Holding a button repeats the step.
- **Keyboard.** Arrows step by `step`, Shift or Page Up/Down by `largeStep`, Home/End go to `min`/`max`, Enter commits, Escape restores the last committed value.
- **Conveniences, all off by default.** `selectOnFocus`, `wheel`, `shorthand` (1.5k → 1500) and `expressions` (`=120*3` → 360). An expression is remembered while the field is mounted: the field shows the result, and the expression again when focused, so it can be edited. `expressions` requires `invalidExpressionLabel` and `calculatedFromLabel(expression)`.
- **Negatives for screen readers.** `aria-valuetext` is the number formatted for the locale with its minus sign ("-$1,234.50"), never parentheses or a word, so screen readers speak it in their own language.

## Select

```tsx
import { SelectControl } from "@aureus-core/ui/components/select-control";
import { SelectField } from "@aureus-core/ui/components/select-field";

<SelectField label="Country" options={countries} placeholder="Choose a country" />
<SelectField
  label="Country"
  options={countries}
  searchable
  searchLabel="Search countries"           // required by `searchable`
  noResultsMessage="No country matches"    // optional: nothing is shown without it
/>
<SelectControl
  name="tags"
  label="Tags"
  options={tags}
  multiple
  multipleDisplay="chips"
  removeChipLabel={(option) => `Remove ${option.label}`}   // required by chips
/>
```

- **Single or multiple.** The value is `string | null`, or `string[]` with `multiple`. With `multiple`, `multipleDisplay` is required: `"chips"` (removable tags; the field grows) or `"summary"` (one line you write in `renderSummary`).
- **Search inside the list.** `searchable` adds a search box at the top of the popup; local filtering ignores case and accents. For server search pass `filter={false}`, load the options in `onSearchChange` and set `optionsLoading`.
- **Opt-in extras.** Groups (`group`), descriptions, disabled options, `maxSelected`, `selectAll` and `creatable`, each independent of the others.

## Checkbox

```tsx
import { CheckboxControl } from "@aureus-core/ui/components/checkbox-control";
import { CheckboxField } from "@aureus-core/ui/components/checkbox-field";

<CheckboxField checkboxLabel="Remember me" />                                   // true / false
<CheckboxField label="Notifications" checkboxLabel="Weekly digest" />           // two texts
<CheckboxControl name="active" checkboxLabel="Active" checkedValue="S" uncheckedValue="N" />
<CheckboxField checkboxLabel="Compact mode" checkboxPosition="end" appearance="card" />
```

- **Two texts.** `label` sits above, as in every field; `checkboxLabel` sits beside the box and is clickable (links inside it still navigate). With both, `label` names the group and `checkboxLabel` names the box.
- **The value is `boolean`,** or the custom values you pass with `checkedValue` and `uncheckedValue` (both or neither; the type is inferred). Schemas such as `z.literal(true)` (accept terms) or `z.enum(["S", "N"])` work directly.
- **Opt-in extras.** `indeterminate` (visual mixed state), `checkboxPosition="end"` and `appearance="card"`, each independent.

## Checkbox group

```tsx
import { CheckboxGroupControl } from "@aureus-core/ui/components/checkbox-group-control";
import { CheckboxGroupField } from "@aureus-core/ui/components/checkbox-group-field";

<CheckboxGroupField label="Channels" options={channels} />                    // string[]
<CheckboxGroupControl name="permissions" label="Permissions" options={permissions}
  selectAll={{ label: "All permissions" }} maxSelected={3} />
<CheckboxGroupField label="Working days" options={weekdays} columns={3} />
```

- **The value is a `string[]` in the order of `options`,** whatever order the boxes are checked in. Schemas such as `z.array(z.string()).min(1)` hold the rules.
- **Opt-in extras.** `selectAll` (its `label` is required), `maxSelected` with an optional `maxSelectedMessage`, `orientation="horizontal"`, `columns` (collapsing in narrow containers), `appearance="card"` and `checkboxPosition="end"`.
- **Naming.** The `label` names the group and each option's label names its box. `required` marks the label only.

## Radio group

```tsx
import { RadioGroupControl } from "@aureus-core/ui/components/radio-group-control";
import { RadioGroupField } from "@aureus-core/ui/components/radio-group-field";

<RadioGroupField label="Plan" options={plans} />                               // string | null
<RadioGroupField label="Billing" options={billing} appearance="segmented" orientation="horizontal" />
<RadioGroupControl name="source" label="Source" options={sources}
  otherOption={{ label: "Other", inputLabel: "Tell us how you found us" }} />
```

- **Exactly one option at a time.** The value is `string | null` (`null` until something is chosen), and schemas such as `z.string({ error })` hold the rules.
- **Keyboard:** the group is one tab stop, and the arrow keys move and select, skipping disabled options.
- **Opt-in extras.** `orientation="horizontal"`, `columns`, `appearance` (`card` or `segmented`), `radioPosition="end"`, `otherOption` (its `label` and `inputLabel` are required; the value becomes the typed text) and `deselectable` (it departs from the standard pattern).

## Switch

```tsx
import { SwitchControl } from "@aureus-core/ui/components/switch-control";
import { SwitchField } from "@aureus-core/ui/components/switch-field";

<SwitchField switchLabel="Email notifications" />                              // true / false
<SwitchField switchLabel="Compact mode" switchPosition="end" size="sm" />
<SwitchControl name="alerts" switchLabel="Alerts"
  onBeforeChange={(next) => api.save("alerts", next)} />                       // spinner in the thumb while saving
```

- **Switch or checkbox?** A switch applies immediately (a setting); a checkbox is confirmed later with a button (terms in a form).
- **The value is a `boolean`,** or custom values with `checkedValue`/`uncheckedValue` (both or neither), as in the checkbox.
- **`onBeforeChange`** confirms each change: while its promise is pending the switch stays put with a spinner in the thumb; only confirmed changes are reported (and stored by the control).
- **Opt-in extras.** `switchPosition="end"`, `appearance="card"`, `size="sm"`, and decorative `stateLabels` and `thumbIcons` (both entries required).

## OTP

```tsx
import { OtpControl } from "@aureus-core/ui/components/otp-control";
import { OtpField } from "@aureus-core/ui/components/otp-field";

<OtpField label="Verification code" length={6} onComplete={verify} />
<OtpField label="Recovery code" length={6} groups={[3, 3]} charset="alphanumeric" uppercase />
<OtpControl name="pin" label="PIN" length={4} masked reveal={{ showLabel: "Show PIN", hideLabel: "Hide PIN" }} />
```

- **One real input behind the boxes,** so SMS autofill (`autocomplete="one-time-code"`), pasting (`"123 456"` → `123456`) and screen readers work as with any input. The boxes are decorative.
- **The value is a `string`;** `onComplete(code)` fires when the last box is filled, and `submitOnComplete` (opt-in) submits the form.
- **Opt-in extras.** `charset` (also sets the mobile keyboard), `uppercase`, `groups` with a `separator`, `masked` with an optional `reveal` (both texts required). Codes keep a left-to-right order in RTL.

## File

```tsx
import { FileControl } from "@aureus-core/ui/components/file-control";
import { diffFiles, toExistingFiles, toFormData } from "@aureus-core/ui/components/file-field";

// Update form: the backend returns { id, url, filename, bytes } for each stored file.
const form = useForm({ defaultValues: { attachments: toExistingFiles(stored, (file) => file.id) } });

<FileControl
  name="attachments"
  label="Attachments"
  multiple
  accept="image/*,.pdf"
  maxSize={10_000_000}
  dropzone
  dropzoneText="Drag files here"
  chooseLabel="Choose files"
  removeLabel={(name) => `Remove ${name}`}
  getFileInfo={(file: Stored) => ({ name: file.filename, url: file.url, size: file.bytes })}
/>;

// On submit: send only what changed.
const { removed } = diffFiles(form.formState.defaultValues?.attachments, values.attachments);
const body = toFormData(values.attachments, "files");
body.append("removed", JSON.stringify(removed.map((file) => file.id)));
```

- **One value for create and update forms.** Each item is `new` (a `File` picked now) or `existing` (your backend's data, of any type, shown through `getFileInfo`). Put the stored files in `defaultValues` with `toExistingFiles`; `diffFiles` returns the files to upload, the stored files kept and the stored files removed.
- **Send files as `FormData`.** `toFormData` appends the new files under a field name. Base64 (`fileToBase64`) is about a third larger and reads each file into memory: use it only when the backend requires it.
- **Immediate upload (opt-in).** `upload(file, { signal, onProgress })` uploads each file as soon as it is picked and resolves with your backend's data; the item then becomes `existing`, in place. Progress, cancel and retry are built in. To block the submit while uploads are pending, refine the schema with `hasPendingUploads`: `z.array(…).refine((files) => !hasPendingUploads(files), "…")`.
- **Opt-in extras, each independent.** Restrictions (`accept`, sizes, `maxFiles`), `appearance="grid"` or `"single"`, a `dropzone`, `reorderable`, `pasteable`, `capture` (camera on mobile) and `transform` (compress or resize before adding).
- **The focusable control is the native file input,** presented as a button, so it carries the name, the description and `aria-required`. Rejected files are reported through `onReject` and, with `rejectionMessage`, announced in your words.
- **Validate on the server.** `accept` and the sizes guide people and the picker; they are not a security control.

## Avatar

```tsx
import { AvatarControl } from "@aureus-core/ui/components/avatar-control";
import { toExistingFile } from "@aureus-core/ui/components/file-field";

// Update form: the backend returns { id, url, filename } for the stored photo, or null.
const form = useForm({ defaultValues: { photo: user.photo ? toExistingFile(user.photo, (p) => p.id) : null } });

<AvatarControl
  name="photo"
  label="Profile photo"
  initialsFrom={user.name}
  getFileInfo={(photo: Photo) => ({ name: photo.filename, url: photo.url })}
  chooseLabel="Upload photo"
  changeLabel="Change photo"
  inspectLabel={(name) => `View ${name}`}
  dialogTitle="Profile photo"
  closeLabel="Close"
  removable
  removeLabel="Remove photo"
/>;
```

- **The File Field model, with one item.** The value is the stored photo (`existing`, your backend's data), a new one (`new`, a `File`) or `null`, so `diffFiles`, `toFormData` and `upload` work as with files.
- **Fallback.** Without a photo, or when its URL fails, the avatar shows your `fallback`, the initials of `initialsFrom`, or a user icon.
- **The circular button.** A round camera button on the avatar's bottom corner picks or changes the photo. It is the native file input, so it carries `required`, the error state and the focus on a failed submit; `chooseLabel` and `changeLabel` name it.
- **Only showing (`readOnly`).** No button, and no change, edit or remove action: the avatar only opens the dialog to look at the photo. Use it for profile pages and headers.
- **The dialog.** With a photo, the avatar is a button that opens a dialog with the large photo: change and close, plus `removable`, `downloadable`, `dropzone` and `pasteable` (each opt-in).
- **The editor (`editable`).** Crop with zoom (drag, or the arrow keys and `+`/`-`), rotate by 90°, flip, reset. Applying exports a square image (`outputType`, `outputSize`, `outputQuality`) that becomes a new photo. The export never upscales beyond the source pixels.
- **CORS.** Editing a stored photo reads its pixels, so its server must send `Access-Control-Allow-Origin`. Without it, `onEditError` receives `reason: "cors"` and nothing changes. Displaying the photo never needs CORS.

## Slider

```tsx
import { SliderControl } from "@aureus-core/ui/components/slider-control";

// The form holds [low, high]; the schema validates the span.
const schema = z.object({
  price: z.tuple([z.number(), z.number()]).refine(([low, high]) => high - low >= 100, "The range must span at least 100."),
});

<SliderControl
  name="price"
  label="Price"
  range
  min={0}
  max={1000}
  step={10}
  thumbLabels={["Minimum price", "Maximum price"]}
  locale="es-ES"
  formatOptions={{ style: "currency", currency: "EUR", maximumFractionDigits: 0 }}
  showValue="header"
  marks={[{ value: 0, label: "0 €" }, { value: 500 }, { value: 1000, label: "1000 €" }]}
  withInput
  inputLabels={["From", "To"]}
/>;
```

- **One value or a range.** The value is a `number`, or with `range` a sorted `[low, high]` with two thumbs. Without `minDistance` a thumb dragged past the other one becomes the other end; with it, a dragged thumb stops at that distance. With the keyboard a thumb never passes the other one.
- **One formatter.** `locale` with `formatOptions` (currency, percent, unit), or your `formatValue`, formats the header value, the tooltips and each thumb's `aria-valuetext`. A range in the header uses `formatRange`.
- **Opt-in extras, each independent.** `showValue` (`"header"` or `"tooltip"`), `marks` with optional labels, `snapToMarks`, `withInput` (one or two number inputs that commit on Enter or blur) and `orientation="vertical"`.
- **Every key follows the props.** Arrows step, Page Up / Page Down use `largeStep`, Home and End go to the limits, and with `snapToMarks` they all move by marks.
- **`onValueCommit` for the end of an interaction.** `onValueChange` (and the form value of the control) follows the thumb while it moves; `onValueCommit` runs once when a drag ends, a key changes the value or an input commits, which suits requests.

## Messages are the developer's

No field or control ships **texts of its own**, neither visible nor accessible. The developer writes every text, in their language, for the situation where it appears. Only developer messages are in English: development warnings and errors such as a control used outside its `FormProvider`.

- **Visible messages are optional.** `placeholder`, `helperText`, `errorMessage`, `emptyMessage`, `noResultsMessage`, `optionsLoadingMessage` and `maxSelectedMessage` render nothing when they are omitted: there is no fallback text in another language.
- **The texts a feature needs are required when the feature is enabled.** TypeScript rejects the props without them (a runtime boolean such as `loading={isSaving}` counts as enabled), and plain JavaScript gets a development warning that names the missing prop:

| Family | Feature | Requires |
| ------ | ------- | -------- |
| Every field (Switch: only `info`) | `loading` | `loadingLabel` |
| Every field | `info` | `infoLabel` |
| Every field | no `label` | `aria-label` or `aria-labelledby` (a warning only) |
| Password | always (the toggle is always shown) | `showPasswordLabel` and `hidePasswordLabel` |
| Text area | `showCount` | `countLabel(count, maxLength?)` |
| Number | step buttons (shown unless `stepper={false}`) | `incrementLabel` and `decrementLabel` |
| Number | `expressions` | `invalidExpressionLabel` and `calculatedFromLabel(expression)` |
| Select | `searchable` | `searchLabel` |
| Select | `clearable` | `clearLabel` |
| Select | `multiple` + `multipleDisplay="chips"` | `removeChipLabel(option)` |
| Select | `multiple` + `multipleDisplay="summary"` | `renderSummary(selected)` |
| Select | `selectAll` | `selectAll.label` |
| Select | `creatable` | `createLabel(query)` and `onCreate(query)` |
| Radio group | `otherOption` | `otherOption.label` and `otherOption.inputLabel` |
| Switch | `stateLabels` / `thumbIcons` | both `on` and `off` |
| OTP | `masked` + `reveal` | `reveal.showLabel` and `reveal.hideLabel` |
| File | always | `chooseLabel`, `removeLabel(name)` and `getFileInfo(data)` |
| File | `dropzone` | `dropzoneText` |
| File | `appearance="single"` | `replaceLabel(name)` |
| File | `upload` | `uploadProgressLabel`, `cancelUploadLabel`, `retryUploadLabel` and `uploadErrorText` (each from the file's name) |
| File | `reorderable` | `moveLabel(name)` and `moveAnnouncement(name, position, total)` |
| Avatar | always | `getFileInfo(data)`, `inspectLabel(name)`, `dialogTitle` and `closeLabel` |
| Avatar | unless `readOnly` | `chooseLabel` and `changeLabel` (names of the circular button) |
| Avatar | `removable` / `downloadable` / `dropzone` | `removeLabel` / `downloadLabel` / `dropzoneText` |
| Avatar | `editable` | `editLabel`, `cropAreaLabel`, `zoomLabel`, `rotateLeftLabel`, `rotateRightLabel`, `flipHorizontalLabel`, `flipVerticalLabel`, `resetLabel`, `applyLabel` and `cancelLabel` |
| Avatar | `upload` | the same four texts as File |
| Slider | `range` | `thumbLabels` (the names of the low and high thumbs) |
| Slider | `withInput` | `inputLabel`, or `inputLabels` with `range` |

The Switch's loading spinner is decorative (`aria-busy` announces the state), so it needs no text. A test over the library source fails when a component ships a hard-coded text.

# Fields y controls

Cada tipo de input de `@aureus-core/ui` viene en pareja:

- un **field** (`TextField`) es un input de propósito general. Úsalo en cualquier lugar, controlado o no controlado.
- un **control** (`TextControl`) es el mismo input vinculado a un formulario de react-hook-form.

Con las mismas props, un field y su control renderizan **el mismo markup**, así que un formulario se ve igual uses el que uses. Un control renderiza su field por dentro.

Familias disponibles:

| Familia     | Field           | Control           | Botón dentro del input                          |
| ----------- | --------------- | ----------------- | ----------------------------------------------- |
| Texto       | `TextField`     | `TextControl`     | Opcional y configurable (`action`)              |
| Contraseña  | `PasswordField` | `PasswordControl` | Siempre el de mostrar/ocultar (sin `action`)    |
| Texto multilínea | `TextAreaField` | `TextAreaControl` | Opcional (`action`), en una barra bajo el texto |
| Número      | `NumberField`   | `NumberControl`   | Botones de paso (apilados o split) y una `action` opcional |
| Select      | `SelectField`   | `SelectControl`   | Chevron, limpiar (✕) opcional y una `action` opcional |
| Checkbox    | `CheckboxField` | `CheckboxControl` | Sin marco: una `action` opcional al final de la fila |
| Grupo de checkboxes | `CheckboxGroupField` | `CheckboxGroupControl` | Sin marco: una casilla por opción |
| Grupo de radios | `RadioGroupField` | `RadioGroupControl` | Sin marco: un radio por opción, o segmentos |
| Switch | `SwitchField` | `SwitchControl` | Sin marco: una `action` opcional al final de la fila |
| OTP | `OtpField` | `OtpControl` | Casillas sobre un input; botón mostrar/ocultar y `action` opcionales |
| Archivo | `FileField` | `FileControl` | El botón de elegir (el input de archivos nativo); zona de arrastre y `action` opcionales |
| Avatar | `AvatarField` | `AvatarControl` | Un botón circular con la cámara sobre el avatar; el avatar abre un diálogo (cambiar, editar, quitar, abrir); `action` opcional |
| Slider | `SliderField` | `SliderControl` | Sin marco: una pista con uno o dos thumbs; inputs numéricos y `action` opcionales |

Todas las familias comparten la misma vista, así que todos los campos se ven iguales.

## Usar un control

Los controls siempre se renderizan dentro de un `FormProvider` de react-hook-form. El formulario es dueño de los valores, los valores por defecto y la validación (normalmente un schema pasado mediante un resolver); un control solo recibe el `name` del campo y las props visuales. No hay prop `control` ni `rules`, ni parámetros de tipo que escribir.

```tsx
import { TextControl } from "@aureus-core/ui/components/text-control";
import { zodResolver } from "@hookform/resolvers/zod";
import { FormProvider, useForm } from "react-hook-form";
import { z } from "zod";

const schema = z.object({ username: z.string().min(3, "Usa al menos 3 caracteres.") });

function ProfileForm() {
  const form = useForm({ resolver: zodResolver(schema), defaultValues: { username: "" } });

  return (
    <FormProvider {...form}>
      <form noValidate onSubmit={form.handleSubmit(save)}>
        <TextControl name="username" label="Usuario" required helperText="Visible para otros" />
      </form>
    </FormProvider>
  );
}
```

- **Los mensajes de validación aparecen en el lugar del texto de ayuda.** Mientras el campo tiene un error en el estado del formulario, su mensaje sustituye a `helperText`, el input recibe `aria-invalid` y el mensaje se anuncia. Cuando el valor se corrige, `helperText` vuelve.
- **Pasa siempre `defaultValues`.** `name` es un string, así que TypeScript no detecta un error tipográfico. En desarrollo, un control avisa cuando su `name` no está entre los valores por defecto del formulario.
- **Fuera de un `FormProvider`, un control lanza** un error que lo indica.

## `disabled` frente a `loading`

Los dos hacen que el input no esté disponible, pero significan cosas distintas para el formulario:

| Prop       | Input         | Spinner | Valor enviado |
| ---------- | ------------- | ------- | ------------- |
| `disabled` | deshabilitado | no      | **no**        |
| `loading`  | deshabilitado | sí      | **sí**        |

Usa `loading` mientras compruebas o cargas algo para un campo cuyo valor se debe seguir enviando.

## Props comunes

Todos los fields y controls aceptan estas props:

| Prop                          | Qué hace                                                                                           |
| ----------------------------- | -------------------------------------------------------------------------------------------------- |
| `label`                       | Texto sobre el input, y su nombre accesible.                                                       |
| `required`                    | Asterisco rojo y `aria-required`. No añade ninguna regla de validación.                            |
| `info` / `infoLabel`          | Botón de información al extremo de la fila del label, con un tooltip que también se abre con tap. `infoLabel` da nombre al botón y es obligatorio con `info`. |
| `helperText`                  | Texto bajo el input, parte de su descripción accesible.                                            |
| `loading` / `disabled`        | Ver arriba.                                                                                        |
| `action`                      | Un botón dentro del marco del input: texto o icono, `tooltip` y cualquier prop de botón.           |
| `className` / `classNames`    | Clases extra para la raíz, o por parte: `root`, `header`, `label`, `requiredMark`, `info`, `control`, `input`, `helper`, `action`. |
| `loadingLabel`                | Nombre accesible del spinner, obligatorio con `loading`. No hay texto por defecto.                 |

Un field también recibe `error` y `errorMessage`; un control los obtiene del formulario.

## Contraseña

```tsx
import { PasswordControl } from "@aureus-core/ui/components/password-control";

const toggle = { showPasswordLabel: "Mostrar contraseña", hidePasswordLabel: "Ocultar contraseña" };

<PasswordControl {...toggle} name="password" label="Contraseña" required />
<PasswordControl {...toggle} name="confirm" label="Repetir contraseña" autoComplete="new-password" />
```

- **Los nombres del botón son tuyos.** `showPasswordLabel` y `hidePasswordLabel` son siempre obligatorios, porque el botón siempre se muestra.
- **El botón viene incluido.** Muestra u oculta la contraseña, tiene `aria-pressed` y deja el foco y el cursor en el input al pulsarlo. Al enviar el formulario, la contraseña se vuelve a ocultar. No hay prop `action`.
- **Visibilidad controlada.** Pasa `visible` y `onVisibleChange` para manejar varios campos a la vez, por ejemplo desde un checkbox "Mostrar contraseñas". `defaultVisible` fija el estado inicial en modo no controlado.
- **Autocompletado.** Por defecto es `current-password` (acceso). Usa `new-password` en formularios de registro y de cambio de contraseña, para que los gestores de contraseñas ofrezcan generar una.
- **Confirmación.** Pon la regla de coincidencia en el schema, sobre la ruta de la confirmación (con zod, un `refine` con `path: ["confirm"]`); su mensaje aparece en ese control.

## Texto multilínea

```tsx
import { TextAreaField } from "@aureus-core/ui/components/text-area-field";

<TextAreaField
  label="Comentario"
  minRows={3}
  maxRows={8}
  maxLength={280}
  showCount
  countLabel={(count, max) => `Quedan ${(max ?? 0) - count} caracteres`}
  actionShortcut
  action={{ children: "Publicar", variant: "default", onClick: publicar }}
/>;
```

- **Altura en vivo.** El campo crece con su contenido de `minRows` a `maxRows` líneas y luego hace scroll. El usuario también puede arrastrarlo para hacerlo más alto o más bajo; la altura que elige pasa a ser el nuevo mínimo. `resize={false}` quita el asa.
- **Barra inferior.** El spinner, el contador y la `action` van en una barra pegada al borde de abajo del marco, así el botón acompaña cualquier cambio de altura y nunca tapa el texto. La barra solo aparece cuando tiene algo que mostrar.
- **Contador.** `showCount` muestra "cuenta/maxLength" (o solo la cuenta) y se pone en rojo al llegar al límite. Exige `countLabel(count, maxLength?)`, el texto que reciben los lectores de pantalla en la descripción del campo, anunciado cuando el usuario deja de escribir. Tú decides si dice lo que queda o lo escrito.
- **Atajo.** `actionShortcut` permite pulsar la acción con Ctrl+Enter (Cmd+Enter en macOS); Enter solo sigue haciendo un salto de línea.

## Número

```tsx
import { NumberControl } from "@aureus-core/ui/components/number-control";
import { NumberField } from "@aureus-core/ui/components/number-field";

const pasos = { incrementLabel: "Aumentar", decrementLabel: "Disminuir" };

<NumberField {...pasos} label="Cantidad" min={0} />                          // 122345
<NumberField {...pasos} label="Unidades" grouping />                         // 123,345
<NumberField {...pasos} label="Presupuesto" currency="USD" decimals={0} grouping /> // $ 12,000
<NumberField label="Tasa" suffix="%" decimals={3} stepper={false} />         // 4.125 %
<NumberControl {...pasos} name="amount" label="Importe" currency="USD" decimals={2} padDecimals grouping />
```

- **Cada prop es independiente y opcional.** Sin props, el campo muestra los dígitos tal como se escriben. `grouping`, `decimals`, `padDecimals`, `currency`, `prefix`, `suffix`, `align` y el formato de negativos nunca cambian los valores por defecto de las demás: `currency` solo añade un símbolo. La implementación decide qué combinación es la correcta.
- **El valor es `number | null`.** El control guarda un número en el formulario, así schemas como `z.number()` funcionan directamente.
- **Botones de paso.** `stepperLayout="stacked"` (▲▼ al final) o `"split"` (− y + a cada lado); en pantallas táctiles, el apilado pasa a split automáticamente. `stepper={false}` los oculta. Mientras se muestran, `incrementLabel` y `decrementLabel` son obligatorios. Mantener pulsado un botón repite el paso.
- **Teclado.** Las flechas suman `step`, Shift o Re Pág/Av Pág suman `largeStep`, Inicio/Fin van a `min`/`max`, Enter confirma y Escape restaura el último valor confirmado.
- **Comodidades, todas desactivadas por defecto.** `selectOnFocus`, `wheel`, `shorthand` (1.5k → 1500) y `expressions` (`=120*3` → 360). Una expresión se recuerda mientras el campo está montado: se ve el resultado y, al enfocarlo, vuelve la expresión para editarla. `expressions` exige `invalidExpressionLabel` y `calculatedFromLabel(expression)`.
- **Negativos para lectores de pantalla.** `aria-valuetext` es el número formateado según el locale con su signo menos ("-$1,234.50"), nunca con paréntesis ni con una palabra, así los lectores de pantalla lo leen en su propio idioma.

## Select

```tsx
import { SelectControl } from "@aureus-core/ui/components/select-control";
import { SelectField } from "@aureus-core/ui/components/select-field";

<SelectField label="País" options={countries} placeholder="Elige un país" />
<SelectField
  label="País"
  options={countries}
  searchable
  searchLabel="Buscar país"                  // obligatorio con `searchable`
  noResultsMessage="Ningún país coincide"    // opcional: sin él no se muestra nada
/>
<SelectControl
  name="tags"
  label="Etiquetas"
  options={tags}
  multiple
  multipleDisplay="chips"
  removeChipLabel={(option) => `Quitar ${option.label}`}   // obligatorio con chips
/>
```

- **Simple o múltiple.** El valor es `string | null`, o `string[]` con `multiple`. Con `multiple`, `multipleDisplay` es obligatorio: `"chips"` (etiquetas removibles; el campo crece) o `"summary"` (una línea que escribes en `renderSummary`).
- **Búsqueda dentro de la lista.** `searchable` añade un buscador arriba del desplegable; el filtrado local ignora mayúsculas y acentos. Para buscar en servidor pasa `filter={false}`, carga las opciones en `onSearchChange` y activa `optionsLoading`.
- **Extras opcionales.** Grupos (`group`), descripciones, opciones deshabilitadas, `maxSelected`, `selectAll` y `creatable`, cada uno independiente de los demás.

## Checkbox

```tsx
import { CheckboxControl } from "@aureus-core/ui/components/checkbox-control";
import { CheckboxField } from "@aureus-core/ui/components/checkbox-field";

<CheckboxField checkboxLabel="Recordarme" />                                    // true / false
<CheckboxField label="Notificaciones" checkboxLabel="Resumen semanal" />        // dos textos
<CheckboxControl name="active" checkboxLabel="Activo" checkedValue="S" uncheckedValue="N" />
<CheckboxField checkboxLabel="Modo compacto" checkboxPosition="end" appearance="card" />
```

- **Dos textos.** `label` va arriba, como en todo field; `checkboxLabel` va junto a la casilla y es clicable (los enlaces que contenga siguen navegando). Con los dos, `label` nombra el grupo y `checkboxLabel` nombra la casilla.
- **El valor es `boolean`,** o los valores que pases con `checkedValue` y `uncheckedValue` (los dos o ninguno; el tipo se infiere). Schemas como `z.literal(true)` (aceptar términos) o `z.enum(["S", "N"])` funcionan directamente.
- **Extras opcionales.** `indeterminate` (estado mixto visual), `checkboxPosition="end"` y `appearance="card"`, cada uno independiente.

## Grupo de checkboxes

```tsx
import { CheckboxGroupControl } from "@aureus-core/ui/components/checkbox-group-control";
import { CheckboxGroupField } from "@aureus-core/ui/components/checkbox-group-field";

<CheckboxGroupField label="Canales" options={channels} />                     // string[]
<CheckboxGroupControl name="permissions" label="Permisos" options={permissions}
  selectAll={{ label: "Todos los permisos" }} maxSelected={3} />
<CheckboxGroupField label="Días laborables" options={weekdays} columns={3} />
```

- **El valor es un `string[]` en el orden de `options`,** sin importar el orden en que se marquen. Las reglas van en schemas como `z.array(z.string()).min(1)`.
- **Extras opcionales.** `selectAll` (su `label` es obligatorio), `maxSelected` con un `maxSelectedMessage` opcional, `orientation="horizontal"`, `columns` (se reducen en contenedores estrechos), `appearance="card"` y `checkboxPosition="end"`.
- **Nombres.** El `label` nombra el grupo y el label de cada opción nombra su casilla. `required` solo marca el label.

## Grupo de radios

```tsx
import { RadioGroupControl } from "@aureus-core/ui/components/radio-group-control";
import { RadioGroupField } from "@aureus-core/ui/components/radio-group-field";

<RadioGroupField label="Plan" options={plans} />                               // string | null
<RadioGroupField label="Facturación" options={billing} appearance="segmented" orientation="horizontal" />
<RadioGroupControl name="source" label="Origen" options={sources}
  otherOption={{ label: "Otro", inputLabel: "Cuéntanos cómo nos conociste" }} />
```

- **Una sola opción a la vez.** El valor es `string | null` (`null` mientras no se elija nada), y las reglas van en schemas como `z.string({ error })`.
- **Teclado:** el grupo es una sola parada de Tab, y las flechas mueven y seleccionan, saltando las opciones deshabilitadas.
- **Extras opcionales.** `orientation="horizontal"`, `columns`, `appearance` (`card` o `segmented`), `radioPosition="end"`, `otherOption` (su `label` e `inputLabel` son obligatorios; el valor pasa a ser lo escrito) y `deselectable` (se aparta del patrón estándar).

## Switch

```tsx
import { SwitchControl } from "@aureus-core/ui/components/switch-control";
import { SwitchField } from "@aureus-core/ui/components/switch-field";

<SwitchField switchLabel="Notificaciones por correo" />                         // true / false
<SwitchField switchLabel="Modo compacto" switchPosition="end" size="sm" />
<SwitchControl name="alerts" switchLabel="Alertas"
  onBeforeChange={(next) => api.save("alerts", next)} />                       // spinner en el thumb mientras guarda
```

- **¿Switch o checkbox?** Un switch se aplica al momento (un ajuste); un checkbox se confirma después con un botón (términos en un formulario).
- **El valor es un `boolean`,** o valores personalizados con `checkedValue`/`uncheckedValue` (los dos o ninguno), como en el checkbox.
- **`onBeforeChange`** confirma cada cambio: mientras su promesa está pendiente el switch no se mueve y muestra un spinner en el thumb; solo se emiten (y el control solo guarda) los cambios confirmados.
- **Extras opcionales.** `switchPosition="end"`, `appearance="card"`, `size="sm"`, y `stateLabels` y `thumbIcons` decorativos (las dos entradas obligatorias).

## OTP

```tsx
import { OtpControl } from "@aureus-core/ui/components/otp-control";
import { OtpField } from "@aureus-core/ui/components/otp-field";

<OtpField label="Código de verificación" length={6} onComplete={verify} />
<OtpField label="Código de recuperación" length={6} groups={[3, 3]} charset="alphanumeric" uppercase />
<OtpControl name="pin" label="PIN" length={4} masked reveal={{ showLabel: "Mostrar PIN", hideLabel: "Ocultar PIN" }} />
```

- **Un solo input real detrás de las casillas,** así el autocompletado de SMS (`autocomplete="one-time-code"`), el pegado (`"123 456"` → `123456`) y los lectores de pantalla funcionan como en cualquier input. Las casillas son decorativas.
- **El valor es un `string`;** `onComplete(code)` se llama al llenar la última casilla, y `submitOnComplete` (opcional) envía el formulario.
- **Extras opcionales.** `charset` (también ajusta el teclado móvil), `uppercase`, `groups` con un `separator`, `masked` con un `reveal` opcional (los dos textos obligatorios). Los códigos mantienen el orden de izquierda a derecha en RTL.

## Archivo

```tsx
import { FileControl } from "@aureus-core/ui/components/file-control";
import { diffFiles, toExistingFiles, toFormData } from "@aureus-core/ui/components/file-field";

// Formulario de edición: el backend devuelve { id, url, filename, bytes } por cada archivo guardado.
const form = useForm({ defaultValues: { adjuntos: toExistingFiles(guardados, (archivo) => archivo.id) } });

<FileControl
  name="adjuntos"
  label="Adjuntos"
  multiple
  accept="image/*,.pdf"
  maxSize={10_000_000}
  dropzone
  dropzoneText="Arrastra archivos aquí"
  chooseLabel="Elegir archivos"
  removeLabel={(nombre) => `Quitar ${nombre}`}
  getFileInfo={(archivo: Guardado) => ({ name: archivo.filename, url: archivo.url, size: archivo.bytes })}
/>;

// Al enviar: manda solo lo que cambió.
const { removed } = diffFiles(form.formState.defaultValues?.adjuntos, values.adjuntos);
const body = toFormData(values.adjuntos, "files");
body.append("removed", JSON.stringify(removed.map((archivo) => archivo.id)));
```

- **Un solo valor para crear y editar.** Cada elemento es `new` (un `File` elegido ahora) o `existing` (los datos de tu backend, de cualquier tipo, mostrados con `getFileInfo`). Pon los archivos guardados en `defaultValues` con `toExistingFiles`; `diffFiles` devuelve los archivos que subir, los guardados que se mantienen y los guardados que se quitaron.
- **Envía los archivos como `FormData`.** `toFormData` añade los archivos nuevos con un nombre de campo. Base64 (`fileToBase64`) ocupa un tercio más y carga cada archivo en memoria: úsalo solo si el backend lo exige.
- **Subida inmediata (opcional).** `upload(file, { signal, onProgress })` sube cada archivo en cuanto se elige y resuelve con los datos de tu backend; el elemento pasa a ser `existing`, en su sitio. Progreso, cancelar y reintentar vienen incluidos. Para bloquear el envío mientras haya subidas pendientes, refina el schema con `hasPendingUploads`: `z.array(…).refine((files) => !hasPendingUploads(files), "…")`.
- **Extras opcionales e independientes.** Restricciones (`accept`, tamaños, `maxFiles`), `appearance="grid"` o `"single"`, `dropzone`, `reorderable`, `pasteable`, `capture` (cámara en el móvil) y `transform` (comprimir o redimensionar antes de añadir).
- **El control enfocable es el input de archivos nativo,** presentado como un botón, así que lleva el nombre, la descripción y `aria-required`. Los archivos rechazados llegan a `onReject` y, con `rejectionMessage`, se anuncian con tus palabras.
- **Valida en el servidor.** `accept` y los tamaños guían a las personas y al selector; no son un control de seguridad.

## Avatar

```tsx
import { AvatarControl } from "@aureus-core/ui/components/avatar-control";
import { toExistingFile } from "@aureus-core/ui/components/file-field";

// Formulario de edición: el backend devuelve { id, url, filename } de la foto guardada, o null.
const form = useForm({ defaultValues: { foto: usuario.foto ? toExistingFile(usuario.foto, (f) => f.id) : null } });

<AvatarControl
  name="foto"
  label="Foto de perfil"
  initialsFrom={usuario.nombre}
  getFileInfo={(foto: Foto) => ({ name: foto.filename, url: foto.url })}
  chooseLabel="Subir foto"
  changeLabel="Cambiar foto"
  inspectLabel={(nombre) => `Ver ${nombre}`}
  dialogTitle="Foto de perfil"
  closeLabel="Cerrar"
  removable
  removeLabel="Quitar foto"
/>;
```

- **El modelo de File Field, con un solo elemento.** El valor es la foto guardada (`existing`, los datos de tu backend), una nueva (`new`, un `File`) o `null`, así que `diffFiles`, `toFormData` y `upload` funcionan igual que con archivos.
- **Fallback.** Sin foto, o cuando su URL falla, el avatar muestra tu `fallback`, las iniciales de `initialsFrom` o un icono de usuario.
- **El botón circular.** Un botón redondo con una cámara en la esquina inferior del avatar elige o cambia la foto. Es el input de archivos nativo, así que lleva `required`, el estado de error y el foco cuando falla el envío; `chooseLabel` y `changeLabel` le dan nombre.
- **Solo mostrar (`readOnly`).** Sin botón ni acciones de cambiar, editar o quitar: el avatar solo abre el diálogo para ver la foto. Úsalo en páginas de perfil y cabeceras.
- **El diálogo.** Con foto, el avatar es un botón que abre un diálogo con la foto grande: cambiar y cerrar, más `removable`, `downloadable`, `dropzone` y `pasteable` (cada uno opcional).
- **El editor (`editable`).** Recorta con zoom (arrastrando, o con las flechas y `+`/`-`), gira 90°, voltea y restablece. Al aplicar se exporta una imagen cuadrada (`outputType`, `outputSize`, `outputQuality`) que pasa a ser la foto nueva. La exportación nunca amplía más allá de los píxeles de origen.
- **CORS.** Editar una foto guardada lee sus píxeles, así que su servidor debe enviar `Access-Control-Allow-Origin`. Sin él, `onEditError` recibe `reason: "cors"` y no cambia nada. Mostrar la foto nunca necesita CORS.

## Slider

```tsx
import { SliderControl } from "@aureus-core/ui/components/slider-control";

// El formulario guarda [bajo, alto]; el schema valida la amplitud.
const schema = z.object({
  price: z.tuple([z.number(), z.number()]).refine(([low, high]) => high - low >= 100, "El rango debe ser de al menos 100."),
});

<SliderControl
  name="price"
  label="Precio"
  range
  min={0}
  max={1000}
  step={10}
  thumbLabels={["Precio mínimo", "Precio máximo"]}
  locale="es-ES"
  formatOptions={{ style: "currency", currency: "EUR", maximumFractionDigits: 0 }}
  showValue="header"
  marks={[{ value: 0, label: "0 €" }, { value: 500 }, { value: 1000, label: "1000 €" }]}
  withInput
  inputLabels={["Desde", "Hasta"]}
/>;
```

- **Un valor o un rango.** El valor es un `number` o, con `range`, un par ordenado `[bajo, alto]` con dos thumbs. Sin `minDistance`, un thumb que pasa al otro se convierte en el otro extremo; con ella, el thumb arrastrado se detiene a esa distancia. Con el teclado un thumb nunca pasa al otro.
- **Un único formateador.** `locale` con `formatOptions` (moneda, porcentaje, unidad), o tu `formatValue`, formatea el valor de la cabecera, los tooltips y el `aria-valuetext` de cada thumb. Un rango en la cabecera usa `formatRange`.
- **Extras opcionales e independientes.** `showValue` (`"header"` o `"tooltip"`), `marks` con etiquetas opcionales, `snapToMarks`, `withInput` (uno o dos inputs numéricos que confirman con Enter o al salir) y `orientation="vertical"`.
- **Todas las teclas siguen las props.** Las flechas avanzan un paso, Re Pág / Av Pág usan `largeStep`, Inicio y Fin van a los límites y, con `snapToMarks`, todas se mueven por marcas.
- **`onValueCommit` para el final de una interacción.** `onValueChange` (y el valor del formulario en el control) sigue al thumb mientras se mueve; `onValueCommit` se llama una vez al terminar un arrastre, cuando una tecla cambia el valor o cuando un input confirma, lo que viene bien para peticiones.

## Los mensajes son del desarrollador

Ningún field ni control **trae textos propios**, ni visibles ni accesibles. El desarrollador escribe cada texto, en su idioma, para la situación en que aparece. Solo los mensajes para desarrolladores están en inglés: los avisos en desarrollo y errores como el de un control usado fuera de su `FormProvider`.

- **Los mensajes visibles son opcionales.** `placeholder`, `helperText`, `errorMessage`, `emptyMessage`, `noResultsMessage`, `optionsLoadingMessage` y `maxSelectedMessage` no muestran nada si se omiten: no hay texto de reserva en otro idioma.
- **Los textos que necesita una función son obligatorios al activarla.** TypeScript rechaza las props sin ellos (un booleano en tiempo de ejecución, como `loading={isSaving}`, cuenta como activado), y en JavaScript sin tipos aparece un aviso en desarrollo con el nombre de la prop que falta:

| Familia | Función | Exige |
| ------- | ------- | ----- |
| Todos los fields (Switch: solo `info`) | `loading` | `loadingLabel` |
| Todos los fields | `info` | `infoLabel` |
| Todos los fields | sin `label` | `aria-label` o `aria-labelledby` (solo un aviso) |
